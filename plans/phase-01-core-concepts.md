# 第一阶段：Agent 核心概念

> 目标：理解 Agent 是什么，以及它和传统 LLM 应用的区别。  
> 适用对象：前端开发工程师。

---

## 1. 什么是 Agent

### 1.1 通俗理解

Agent（智能体）是一种能够**自主感知环境、做出决策并执行动作**的系统。  
在 AI 领域，Agent 通常指由大语言模型（LLM）驱动，能够根据目标自动规划、调用工具、完成任务程序。

可以把 Agent 理解为一个"会思考的打工人"：

- 你给它一个目标（比如"帮我查一下北京明天的天气"）
- 它会自己思考怎么完成
- 需要查资料时，它会调用工具
- 最后把结果返回给你

### 1.2 Agent 与普通 LLM 应用的区别

| 特性 | 普通 LLM 应用 | Agent |
|------|--------------|-------|
| 交互方式 | 一问一答 | 多轮自主执行 |
| 是否调用外部工具 | 否 | 是 |
| 是否有记忆 | 通常无 | 有 |
| 任务完成方式 | 单次生成 | 规划 → 执行 → 观察 → 再规划 |
| 典型场景 | 聊天、文案生成 | 自动化任务、复杂问题求解 |

**举例：**

- 普通 LLM 应用：你问"北京明天天气怎么样？"，它回答"我不知道实时数据"。
- Agent：你问"北京明天天气怎么样？"，它会调用天气 API，拿到数据后再回答你。

## 2. Agent 的核心组成

一个典型的 Agent 由以下四部分组成：

```
┌─────────────────────────────────────────┐
│                 Agent                    │
│  ┌─────────┐ ┌─────── ┌──────┐ ┌─────┐ │
│  │   LLM   │ │ 规划  │ │ 记忆 │ │ 工具 │ │
│  └─────────┘ └───────┘ └──────┘ └─────┘ │
└─────────────────────────────────────────┘
```

### 2.1 LLM（大脑）

LLM 是 Agent 的核心推理引擎，负责：

- 理解用户意图
- 决定下一步做什么
- 生成工具调用参数
- 总结结果并回复用户

常见模型：GPT-4、Claude、Gemini、Llama 等。

### 2.2 规划（Planning）

规划能力让 Agent 能够拆解复杂任务，分步骤执行。

例如任务"帮我安排一次上海三日游"，Agent 会拆解为：

1. 查询上海的景点
2. 查询酒店信息
3. 规划每日行程
4. 输出旅行计划

常见规划模式：

- **CoT（Chain of Thought）**：让模型一步步思考
- **ReAct**：思考 → 行动 → 观察，循环执行
- **Plan-and-Execute**：先制定完整计划，再逐步执行

### 2.3 记忆（Memory）

记忆让 Agent 能够记住上下文，避免"失忆"。

| 类型 | 说明 | 例子 |
|------|------|------|
| 短期记忆 | 当前对话上下文 | 用户上一句话说了什么 |
| 长期记忆 | 持久化存储的信息 | 用户偏好、历史记录 |

前端类比：

- 短期记忆 ≈ React 的 state
- 长期记忆 ≈ localStorage / 数据库

### 2.4 工具（Tools）

工具是 Agent 与外部世界交互的方式。常见工具：

- 搜索工具（Google、Bing）
- 计算工具（计算器）
- API 调用（天气、股票、地图）
- 数据库查询
- 文件操作

工具通常以函数形式提供给 Agent，Agent 决定何时调用哪个工具。

## 3. 经典 Agent 范式

### 3.1 ReAct（Reasoning + Acting）

ReAct 是最经典的 Agent 范式之一，核心循环：

```
Thought（思考） → Action（行动） → Observation（观察）
```

**示例：**

> 用户问："北京今天的气温是多少？"

Agent 的思考过程：

1. **Thought**：用户想知道北京今天的气温，我需要调用天气工具。
2. **Action**：调用 `get_weather(city="北京")`。
3. **Observation**：工具返回 `{ "temperature": 25, "condition": "晴" }`。
4. **Thought**：我已经拿到数据，可以回复用户了。
5. **Final Answer**：北京今天气温 25℃，晴天。

### 3.2 Plan-and-Execute

Plan-and-Execute 先制定完整计划，再执行：

1. 接收任务
2. 制定计划（Plan）
3. 按步骤执行（Execute）
4. 汇总结果并返回

适合步骤明确、可并行化的任务。

### 3.3 Reflexion

Reflexion 让 Agent 能够自我反思：

- 执行任务后，评估结果
- 如果结果不好，分析原因
- 调整策略，重新尝试

适合需要迭代优化的场景。

## 4. 工具调用（Function Calling）

### 4.1 什么是工具调用

工具调用是 Agent 使用外部能力的方式。LLM 根据用户输入，判断是否需要调用某个函数，并生成函数参数。

### 4.2 工具调用流程

```
用户输入
   ↓
LLM 判断需要调用工具
   ↓
LLM 生成工具名称和参数
   ↓
程序执行工具函数
   ↓
工具返回结果
   ↓
LLM 根据结果生成最终回复
```

### 4.3 工具定义示例

```json
{
  "name": "get_weather",
  "description": "获取指定城市的天气信息",
  "parameters": {
    "type": "object",
    "properties": {
      "city": {
        "type": "string",
        "description": "城市名称"
      }
    },
    "required": ["city"]
  }
}
```

## 5. 前端工程师如何理解 Agent

可以把 Agent 看作一个更智能的"前端状态机"：

| 前端概念 | Agent 对应概念 |
|----------|----------------|
| 组件 | 工具 / 能力 |
| 状态管理 | 记忆（Memory） |
| 事件处理 | 用户输入 / 工具返回 |
| 路由 | 规划（Planning） |
| API 请求 | 工具调用 |

Agent 的开发思路和前端有很多相似之处，前端工程师上手会比较快。
